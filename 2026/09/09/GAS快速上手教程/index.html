# GAS快速上手教程

适用读者：有蓝图经验、几乎没有C++经验，想用GAS(Gameplay Ability System)做出"能跑、能改、能加功能"的游戏系统。
本文档会以你要做的这款游戏为贯穿示例：第三人称/第一人称可切换 + 近战 + 远程射击 + 简单解谜 + 基于Advanced Sessions与Steam的多人联机。
目标不是让你背原理，而是：照着做一定能做出来，想改一定有明确入口。

# 0. 这份文档能给你什么

  • 一套复制粘贴即可编译的C++骨架（角色基类、属性集、伤害函数库、动画通知），其余尽量用你熟悉的蓝图完成。
  • 每个章节都有：目标 → 步骤 → 验证方法 → 修改入口 → 常见坑。
  • 一套低耦合的组织思路：什么功能该进GAS、什么功能不该进GAS，以及为什么。
  • 多人联机(Advanced Sessions + Steam)的配置与蓝图流程。

# 1. 阅读路线（按顺序，别跳）

章节 内容 你需要花的时间
01 把项目变成C++项目、开启GAS 15分钟
02 七个核心概念 + 整体架构（先看懂这张图） 20分钟
03 角色基类：ASC + 属性集（全项目最核心的C++） 60分钟
04 GameplayEffect：伤害/治疗 + 通用伤害函数库 40分钟
05 第一个技能：近战攻击（蓝图为主） 60分钟
06 远程射击与投射物 40分钟
07 冷却、Buff与状态Tag 30分钟
08 解谜与交互：哪些不该用GAS、怎么设计才低耦合 30分钟
09 多人会话：Advanced Sessions + Steam 60分钟
10 GAS联网要点与检查清单 30分钟
11 修改速查表（以后常回来翻） 用时即查
12 常见错误与排错手册 用时即查

如果你时间紧：03、05 是必读；04 是 05 的前置；其余按需。

# 2. 通用约定（先读，能省很多事）

# 2.1 类名前缀

  • 本文示例代码类名前缀是 G（如 AGCharacterBase、UGAttributeSet）。
  • 如果你已有自己的项目前缀（例如你的项目缩写是KB），把示例里的 G 替换成你的前缀即可。
  • 不要替换 Gameplay、AbilitySystem、UAbilitySystemComponent 等引擎自带的词。

# 2.2 文件放哪里

  • 所有自写C++文件都放进：Source/<你的模块名>/GAS/（.h和.cpp放同一层，例如 Source/KB5p8/GAS/GCharacterBase.h）。
  • 模块名默认与项目名相同（打开 .uproject 同级的 Source 文件夹就能看到）。
  • 蓝图资产建议建 Content/ 下的这些文件夹，命名前缀统一：
    • GA_ = GameplayAbility技能蓝图
    • GE_ = GameplayEffect效果资产
    • BP_ = 普通蓝图（角色、投射物、谜题物）
    • AM_ = 动画蒙太奇
    • IA_ / IMC_ = Enhanced Input动作/映射

# 2.3 C++你要改的地方 vs 不要碰的地方

  • 文档里凡是标注 【改这里】 的代码，就是给你改的（数值、属性名、配置）。
  • 没标注的地方：先照抄。以后理解深了再动，不要"顺手优化"，否则报错时你无法判断是不是自己改坏的。

# 2.4 学习心法

  1. 先跑通，再理解：第一遍别改任何东西，把示例原样做出来，看到"血条会掉、技能会放"再回头读原理。
  2. 改一步，测一步：每次只改一个点，用下面每章的"验证方法"确认没改坏。
  3. 报错三件套：遇到编译/运行错误，先看 Output Log 最上面一条红色 Error，把完整错误文字 + 你刚改过的代码发给我，我们一起改，不要自己瞎试。

# 3. 术语速查表（先扫一眼，用到了再回来看）

术语 一句话解释 你什么时候碰它
ASC (AbilitySystemComponent) 每个角色的"GAS大脑"，管技能、属性、标签 03章创建；以后基本不用手碰
AttributeSet 装属性的"属性包"（Health/Stamina...） 03、04章改属性时
Attribute 一个具体数值，如Health 03、04章
GE (GameplayEffect) "效果"资产：改属性、上Buff、扣血、加冷却 04章起，大量用
GA (GameplayAbility) "技能"蓝图：攻击、射击 05章起
GameplayTag 带层级的小标签：State.Dead、Ability.Melee.Attack 全程
AbilityTask 技能蓝图里的"等待节点"（等动画、等事件） 05章
SetByCaller GE里一个"数值留空、由调用方填"的机制 04章（已被封装，你不用直接碰）
GameplayCue 纯表现反馈（音效/特效），本教程暂不深入 进阶

# 4. 本文档与"以后一起开发"的关系

  • 本文档完成后，你就有了一个可运行、可改的骨架与第一套技能。
  • 之后你拿着这份文档找我开发具体功能（推箱子、火把谜题、悬崖悬挂、会话界面等）时，我会按 08/09 章里定好的边界与接口继续做，不会推倒重来。
